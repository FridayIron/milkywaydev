# 项目经验

## 项目一：全自动免疫分析仪 iStar2000 (POCT)

**时间**：2023.08 - 至今 | **职责**：负责整机下位机功能设计

### 项目介绍

iStar2000 全自动免疫分析仪整机全组件下位机开发，涵盖级联轨道、进样模块、样本移液模块、试剂针模块、双轴机械抓手、旋转开盖/摇匀模块、试剂盘（恒温冷藏）、孵育盘（恒温加热）、光电采集（PMT/HCT）、条码识别等十余类模块。

### 技术选型

- **硬件**：六块 APM32F407 + FPGA / LPC5506 / STM32F103 / 外挂厂商模块（CAN 通信）
- **软件**：MCU（C/C++）前后台方式，业务层功能基于 Qt-C++/Lua 混合命令控制平台
- **通信**：CAN / 232 / 485 / FSMC 协议控制及多模块挂载

### 核心功能

- Bootloader（STM32F103 / LPC5506 / APM32F407ZG）
- 多运动模式步进电机控制
- 温度控制（PID）
- 整机错误故障恢复处理、整机参数缓存处理
- 各组件应用层功能设计

### 关键业绩

- 完成整机全部下位机功能，推进软件平台化建设，完善时序平台
- iStar2000 从 0 到 1 成功发布量产，百台设备投入医院稳定使用
- 荣获 2024 年先进个人

## 项目二：液动样本臂

**时间**：2022.07 - 2023.07 | **职责**：负责模块软硬件功能设计

### 项目介绍

由三轴（XYZ/XRZ）机械臂、液体驱动系统和样本缓冲盘三个部分组成的高精度微量液体转移机械臂，最小移液量 5ul，CV < 3%。涉及液面检测、液面跟随、吸空检测、凝块堵塞检测、管路漏气检测、耗材清点、反应杯扫描、样本就近转移、参数保存、MCU 异常自恢复等功能。

### 技术选型

- **MCU**：LPC1778
- **RTOS**：ThreadX
- **通信**：CAN 命令解析

### 核心工作

1. 梯形加减速算法控制步进电机，多线程实现多电机协同运动，实现闭环控制及失步检测
2. 卡尔曼滤波、均值滤波及状态判断提高液面等检测功能的抗干扰能力
3. 吸液液面跟随；卡尔曼、最小二乘法拟合曲线和快排处理数据，实现凝块堵塞检测及管路漏气检测
4. 耗材清点中采用二分法缩短检测时间
5. 绘制原理图、步进电机控制电路板 PCB、输出通信协议、部件（需求）设计方案、程序流程图等

### 关键业绩

- 重构 MAGLUMI X6-X8「液动样本臂」下位机裸机程序，修复 CAN 通信异常、液位及凝块检测失误等 BUG
- 完成 ThreadX 软件平台的液动样本臂功能开发，实现原理样机模块全功能正常运行
- 完成「Snibe 一次性吸头检测工装」下位机编写，2022 年 8 月投入使用，至今未收到运行异常反馈
- 荣获 MAGLUMI X6 项目研发团队·研究工作中最大贡献奖，特记一等功

## 项目四：IVD 仪器研发 Agent 平台（私有化）

**时间**：2025 - 至今 | **职责**：架构设计与全栈实现（个人/内网交付）

### 项目介绍

本地私有化的 IVD 仪器研发内部 Agent：把架构说明、协议、故障案例、测试规范等沉淀为可检索知识库，并在问答、故障分析、需求评审、报告编写场景中调用大模型生成结构化结论；同时提供账号权限、运维维护与备份能力。

### 技术选型

- **后端**：Python · FastAPI · Uvicorn（同端口托管 API + 静态前端）
- **数据**：SQLite（业务库）· 本地文件 uploads / 向量缓存 · 定期备份
- **检索与模型**：中文 TF-IDF RAG · OpenAI Chat Completions 兼容 LLM（如 DeepSeek；无 Key 可 mock 演示）
- **前端**：静态 HTML / CSS / JS（无重型框架，便于内网零构建交付）
- **安全与权限**：多角色（developer / super / admin / user / guest）· 多账号切换 · SSO 踢下线 · 维护模式

### 核心工作

1. 搭建登录壳 + 主工作台 + 四类 Agent（问答 / 故障 / 评审 / 报告）与知识库管理后台  
2. 对话按用户隔离；知识库分类检索 + 溯源；开发者后台支持备份、用量与维护开关  
3. 配套个人工作计划模块（独立库，与知识库检索解耦）及移动端布局适配  

### 关键业绩

- 形成「权限壳 + 知识入库检索 + Agent 编排 + 模型适配 + 运维后台」可复用五件套，可在内网 Windows 一键启动  
- 相关说明与演示入口见本站模块页 / 博客与本地 `127.0.0.1:8000`

## 项目五：上位–中位–下位通信与职责规范

**时间**：结合产品演进持续沉淀 | **职责**：参与架构评审、协议草案与红线固化

### 项目介绍

面向 IVD 仪器软件网页化与数据反馈，明确上位（人机）、中位（网关/编排）、下位（实时执行）三层职责，固化交互原则与禁止事项，降低联调与发布风险。

### 技术选型

- **分层**：上位 UI · 中位 API/网关 · 下位实时控制  
- **通道思路**：鉴权 Token · 命令白名单与审计 · 配置 API · 监控只读订阅（WS/SSE 方向）  
- **设备侧**：CAN / UART 等总线由中位或专用服务持有，禁止浏览器直连设备口与业务库  

### 核心工作

1. 输出三层职责表与红线（禁止 UI 直连库、禁止 UI 直连设备、禁止无鉴权调试后门进正式包等）  
2. 梳理配置化界面合法路径：配置经中位校验后下发；写操作必须走命令通道  
3. 与现有下位机命令控制 / 时序平台经验对齐，支撑后续中位网关与网页上位演进  

### 关键业绩

- 形成可评审的架构与协议文档基线，便于跨软件 / 系统 / 质量对齐边界

## 项目六：内网 GitLab 与 SVN→Git 迁仓

**时间**：2026 | **职责**：部署、迁仓方案、日常规范与培训

### 项目介绍

为嵌入式软件团队自建内网 GitLab CE，制定 SVN 全历史迁仓与产品组目录约定，并落地日常开发（feature → Merge Request → 合并）培训手册，提升协作效率。

### 技术选型

- **服务端**：Ubuntu · GitLab CE Omnibus · 备份 / cron · Group·Project 权限  
- **迁仓**：`git svn` 保留 revision 历史 · authors 映射 · 产品组树 PC / MC / MX  
- **客户端**：Git · 分支保护（`main` / `release/*`）· SSH/HTTP 接入与本机隧道兜底  
- **文档**：部署命令手册、迁仓方案、日常培训手册（同步至本站博客）

### 核心工作

1. 完成连通摸底、系统准备、Omnibus 安装、关闭公开注册、保护默认分支  
2. 制定「先盘点 → 试迁 1 仓 → 批量 → SVN 只读切换」路径，一编译单元一仓  
3. 编写培训讲义：clone、开分支、提交、提 MR、审阅与合并全流程  

### 关键业绩

- 内网 Web/clone/push 打通；组织与分支规范可复用；Cursor Skills 附件可随博客下载
