# Cache 与 DMA 一致性

> 系列目录：[嵌入式驱动面试手册](/pages/blog/2026-10-20-嵌入式驱动面试手册)

Cortex-M4（STM32F4、APM32F4）没有指令 Cache 和数据 Cache。DMA 和 CPU 看的是同一份 SRAM，对不齐或方向错了，都不是 Cache 造成的。

Cortex-M7（F7、H7）的数据 Cache 行长 32 字节。DMA 不经过 Cache。默认的可缓存 SRAM 是写回：CPU 的存储可能只留在 Cache 里。

| 操作 | 什么时候做 |
|---|---|
| Clean | CPU 写完缓冲，DMA 即将把它发送出去 |
| Invalidate | DMA 已经写入 SRAM，CPU 即将读取。启动接收前也做一次，避免旧行以后写回盖掉新数据 |

按地址维护之后执行 DSB。作废以整行为单位。缓冲要按 32 字节对齐，长度凑满整行，不要紧挨着别的变量，否则作废会丢掉同一行里还没写回的标志。

`volatile` 只约束编译器，不能代替 Cache 维护。

把 DMA 区用 MPU 配成不可缓存的普通内存后，可以不再每次 Clean / Invalidate。MPU 区域大小必须是 2 的幂，基址按大小对齐。外设寄存器保持 Device 属性，不要标成可缓存。

STM32H7 的 DTCM 从 `0x20000000` 起，CPU 能访问，DMA1/DMA2 不能。发送和接收缓冲要放在 AXI SRAM（`0x24000000` 一段）或手册写明 DMA 能到达的 SRAM。F7 的地址划分不同，不要把这条规则原样套过去。

关 D-Cache 就正常、打开就错，就是一致性问题。发送方向缺 Clean，接收方向缺 Invalidate。
