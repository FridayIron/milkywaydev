MCU 直驱步进与「插补」：现网结论与概念对照 ​

对照工程：mechctrlinfra（CYHalMotorMCU）· mcu_framework（motor_speed_profile）
动态图：打开同目录 插补算法动态图.html

1. 一句话结论 ​

现网 MCU 直驱步进没有实现数控意义上的多轴轨迹插补（直线/圆弧/Bresenham/DDA）。
实现的是单轴速度表加减速（Acc → Const → Dec）：按微步推进脉冲频率，保证启停不丢步、运动时间可控。

日常口语里有人把「速度曲线插值 / 脉冲周期刷新」也叫插补，那是另一类问题；本文按数控标准语义区分二者。

2. 两类「插补」不要混 ​

类型解决什么问题典型算法现网 MCU 直驱？
轨迹/路径插补多轴如何同步走出直线、圆弧、样条Bresenham、DDA、数据采样插补无
速度/脉冲时序规划单轴如何从静止加速到巡航再减速梯形/S 曲线、速度表查表有（速度表 Acc/Const/Dec）
text
路径插补（多轴）：   目标路径 → 每个插补周期算出各轴 Δpulse → 各轴发脉冲
单轴速度规划（现网）：目标步数 → 速度表算 Acc/Const/Dec → TIM 改 ARR → 逐脉冲发 STEP

3. 现网 MCU 直驱实际在做什么 ​

3.1 硬件路径 ​

text
应用命令（相对步数 / 找零 / 坐标）
        ↓
CYHalMotorMCU / mfw motor HAL
        ↓  CalcMoveSpeed / mfw_motor_speed_calc
速度表 + 相位机（预加速 / 加速 / 匀速 / 减速）
        ↓  每微步 ISR
TIM 更新 ARR（边沿周期）→ STEP 引脚脉冲 → DRV8711 → 电机

锚点：

层路径
旧工程mechctrlinfra/driver/implement/mcu/cyhalmotormcu.cpp
新框架mcu_framework/src/hal/mcu/motor_speed_profile.c、hal_motor_stm32.c

3.2 速度表加减速（不是路径插补） ​

  • 表长度约 60 档，表值近似微步速率 pps。
  • 边沿周期：us ≈ 1e6 / (pps × step_length)（step_length 默认 2：每 2 微步才升/降一档）。
  • 相位：PRE_ACC → ACC → CONST → DEC → STOPPED。
  • 短行程会自动裁剪加速/减速段，避免步数不够仍硬加速。

这是时间轴上的速度规划，输出仍是一根轴的脉冲串；没有「同时给 X、Y 分配脉冲以贴合直线」的逻辑。

3.3 多电机如何协调 ​

现网多电机通常是：

  • 命令级串行/并行：时序脚本或协议先后发各轴运动；
  • 各轴独立 TIM：各自 Acc/Const/Dec；
  • 无公共插补周期把多轴捆成一条几何轨迹。

因此「推手与皮带同时动」属于调度层并行，不等于路径插补。

4. 什么情况下才需要真正的插补算法 ​

场景为何需要路径插补
平面直线插补（X+Y 同时到点且走直线）必须按比例分配两轴脉冲，否则走折线
圆弧/螺旋每周期按角度增量算两轴 Δstep
多轴联动轮廓（激光、点胶、雕刻）路径精度与速度耦合
电子凸轮 / 主从同步从轴位置是主轴的函数

iS20 机械控制板当前模型以「单机构单轴运动指令」为主（直线推手、盘旋转找初始等），几何轨迹在机构设计里已简化为单自由度，故 MCU 层不做路径插补是合理裁剪。

若未来出现「两轴在平面内走出指定直线/圆弧」，才应新增插补模块（建议独立于现有 motor_speed_profile）。

5. 路径插补如何实现（通用原理，供对照） ​

以下为行业常见做法，不是现网代码。

5.1 脉冲当量与插补周期 ​

  • 把目标路径离散成周期 T（如 1 ms）内的微小线段；
  • 每周期算出各轴应发脉冲数 ΔN_i；
  • 轴内再用定时器把 ΔN_i 摊成均匀/加减速脉冲。

5.2 Bresenham（直线，整数友好） ​

以二维为例，从 (0,0) 到 (Dx, Dy) 且 |Dx| ≥ |Dy|：

  1. 误差项 e = 2·Dy − Dx；
  2. 每步 X 必走 1；若 e ≥ 0 则 Y 也走 1，并 e -= 2·Dx；
  3. 每步 e += 2·Dy。

特点：只需加减，适合 MCU；保证最接近理想直线的栅格路径。

5.3 DDA（数字微分分析） ​

每周期：x += Dx/N，y += Dy/N，取整后与上次位置差得到脉冲。实现简单，浮点/定点数需注意累积误差。

5.4 与现网速度表的叠加关系 ​

真正量产轮廓控制通常是两层：

text
路径插补器（多轴 ΔN） → 各轴速度/加减速整形 → 脉冲发生器

现网只有右侧两层中的「单轴速度表 + TIM」，没有左侧路径插补器。

6. 和现网代码的对应关系（避免误读） ​

代码现象正确理解
CalcMoveSpeed / mfw_motor_speed_calc按总步数切 Acc/Const/Dec
ISR 里改 TIM 周期刷新单轴脉冲频率
多个 CYHalMotorMCU 实例多轴独立驱动，非联动插补
盘电机工位计算 CalcMoveSteps几何换算成步数，仍是单轴一次运动

7. 阅读建议 ​

  1. 先打开 插补算法动态图.html：上排路径/单轴；中部节拍连续进给；下部前瞻（现网用不上，见 §9）。
  2. 再读 mcu_framework/src/hal/mcu/motor_speed_profile.c 看 Acc/Const/Dec。
  3. 需要底层脉冲细节时对照 cyhalmotormcu.cpp 中 STEP 上升沿与速度台阶逻辑。

8. 用现网业务场景举例（概念推演，不改代码） ​

现网常见电机类命令：ExeMotorRest（找零）、ExeMotorMove1（到坐标）、ExeMotorMove3（相对步数）、盘 ExeRandom_Rotate / goto 工位（内部 CalcMoveSteps）。
下面用这些真实业务说明：现在怎么走、什么时候才谈得上插补、若要插补会怎样算。

8.1 场景 A：盘转到指定工位（现网常态 —— 不需要路径插补） ​

业务：试剂/样本盘从当前孔转到目标孔（如孔 3 → 孔 11）。

现网做法（概念）：

text
目标工位 ID
  → CalcMoveSteps：按孔距、圈数、定位偏移算出「这一轴要走多少微步」
  → 单轴 Acc→Const→Dec 发脉冲
  → 到位

这是一维圆周上的点到点。几何只出现在「步数换算」里，运动过程中只有一根旋转轴在动，没有第二轴要跟它凑成直线/圆弧轨迹。
→ 算工位 ≠ 做插补；插补器用不上。

8.2 场景 B：直线推手到坐标 + 盘同时转（现网常见并行 —— 仍不是路径插补） ​

业务：时序里同一拍或相邻拍：推手 ExeMotorMove1 到坐标 C，盘 goto 工位 P（并行调度）。

现网做法（概念）：

text
时序/中位：同时（或先后）下发两条独立运动命令
  推手轴：自己的步数 + 自己的速度表
  盘轴  ：自己的步数 + 自己的速度表
两轴 TIM 各自跑，互不知道对方这一微秒该不该发脉冲

两轴可能「差不多同时结束」，但 Tip/抓手在空间中的路径是两段独立一维运动的合成，一般是折线或不可控曲线，没有「必须走出平面直线」的约束。
→ 这是命令级并行，不是路径插补。

8.3 场景 C：假想「平面直线插补」—— 才需要真正插补 ​

假设未来某模块有两根直线轴 X（横移）、Z（升降），业务要求：
从取液点 A 到排液点 B，Tip 必须沿斜线匀速贴近，不能先抬后移（避免撞盖/挂液）。

设脉冲当量已标定：

轴从 A 到 B 的位移换算微步
X+12.0 mmDx = 2400
Z+7.5 mmDz = 1500

现网若仍用「两次独立 Move」（不满足斜线） ​

text
先 Move X 2400 步（Acc/Const/Dec）→ 再 Move Z 1500 步
或两命令并行：各跑各的速度表

空间轨迹是「折线」或「两轴互不等比的曲线」，不是直线 AB。

若用 Bresenham 直线插补（概念步骤） ​

目标：整段过程中始终近似满足 Δz / Δx ≈ 1500/2400 = 5/8。

  1. 选主轴：|Dx| ≥ |Dz| → 主轴 = X，共插补 2400 步（每步 X 必发 1 脉冲）。
  2. 初始误差：e = 2·Dz − Dx = 3000 − 2400 = 600。
  3. 每插补步（示意）：
    • X 发 1 脉冲；
    • 若 e ≥ 0：Z 也发 1 脉冲，且 e -= 2·Dx；
    • 然后 e += 2·Dz。
  4. 速度层：整条斜线再套一层合成进给速度（或主轴速度表），两轴脉冲由同一个插补节拍产出，而不是两条无关的 ExeMotorMove3。

前几步直觉（缩小比例 Dx=8, Dz=5 更容易脑算，与动态图左图同类）：

步e 判据发脉冲累计 (x,z)
1e≥0 → Z 动ΔX=1, ΔZ=1(1,1)
2…ΔX=1, ΔZ=0 或 1…
…共 8 步后(8,5)

真实 2400/1500 只是把上表拉长，算法相同。

text
路径插补器（每 T 或每主轴步）
    → 本步 ΔNx、ΔNz
    → X/Z 脉冲发生器（仍可带加减速整形）

这才是「业务上要做插补」时的做法；与现网盘 goto、单轴 Move1/Move3 是不同一层。

8.4 场景 D：盘上的「圆弧」要不要插补？ ​

盘电机转到下一孔，物理上走过一段圆弧，但控制上只有 θ 一维（步数 = 角度 × 传动比）。
数控里的「圆弧插补」是 X+Y 两轴去逼近圆弧；你们盘是单轴旋转机构，不需要把圆弧再拆成两轴脉冲。
→ 走圆弧形轨迹的机构 ≠ 软件圆弧插补。

8.5 对照小结（对着现网命令看） ​

业务典型命令/逻辑要路径插补吗？
推手到坐标 / 相对步进Move1 / Move3否（单轴点到点 + 速度表）
盘到工位 / 旋转CalcMoveSteps + 单轴运动否（一维圆周点到点）
推手与盘「一起动」时序并行两条命令否（并行，非联动轨迹）
两直线轴必须走出斜线/平面直线（现网无此产品约束）是（Bresenham/DDA 等）
平面圆弧、复杂轮廓（现网无）是

落地判断句：只有当产品说「两个（及以上）自由度在运动过程中必须满足几何比例/曲线」，才上插补；现网 iS20 机械控制以单自由度机构 + 命令并行为主，所以 MCU 直驱停在速度表即可。

8.6 插补节拍与速度：不是「每拍发完就停」 ​

常见疑问：坐标下发后按节拍算 ΔN，若每拍只走 2 步，速度是不是上不去？是不是等于发了 N 条短 Move？

不是。 节拍只负责「这一小段时间各轴该分多少脉冲」；整段轨迹共用一条进给速度曲线，前后节拍的脉冲在时间上首尾相接。

text
一条运动命令（一个目标 / 一段路径）
        │
        ▼
  进给速度规划（整段 Acc→Const→Dec，只做一次）
        │  每个插补周期 T 给出本拍合成进给 F(t)
        ▼
  路径插补（按比例拆成 ΔNx、ΔNz …）
        │
        ▼
  脉冲发生器连续输出（拍与拍之间不断流）
对比N 条短 Move插补 + 一条速度曲线
启停每条都可能 Acc/Dec整段只加减速一次
轴间比例难保证每拍按几何比例分配
速度上限被反复加减速拖死由 F_max 与脉冲能力决定
体感一顿一顿一条连续斜线/轮廓

速度怎么上得去：若周期 T=1 ms，某拍 ΔN=20，则该拍平均约 20000 pps；下一拍继续发，不回到 0。加减速作用在整段路径的进给 F(t) 上，不是作用在「每一拍单独一条命令」上。

9. 前瞻算法（Look-ahead）——概念说明（现网用不上） ​

动态图：同目录 HTML 「前瞻」 一节。本节只作认知对照，不要求、也不计划在现网 MCU 直驱落地实现。

9.1 它解决什么问题 ​

插补解决的是：一段几何路径里，多轴每拍如何分脉冲。
前瞻解决的是：很多段路径首尾相接时，拐角处要不要每次减速到 0。

典型场景：雕刻/点胶连续折线 A→B→C→D。

做法拐角行为后果
无前瞻每段独立 Acc→Const→Dec，到 B、C 都刹到 0 再启动安全但极慢、顿挫
有前瞻提前看后面若干段，按转角、轴加速度上限算「拐角允许速度」V_corner，段与段速度衔接锐角仍须慢过，钝角可高速带过
text
路径缓冲：段1 | 段2 | 段3 | …
        ↓ 前瞻窗口（看 N 段）
  算各拐角 V_corner、反向推加减速衔接
        ↓
  一条跨多段的进给曲线 F(s)  → 再交给插补节拍出 ΔN

与「单段内一条 F(t)」（§8.6）的关系：

  • §8.6：一段路径内部，拍与拍不断流。
  • 前瞻：多段路径之间，也不在每个拐点强制回零（在动力学允许时）。

9.2 粗略怎么算（仅概念） ​

  1. 缓冲区内已有下一段（或下 N 段）几何。
  2. 在拐点看方向突变：转角越大，允许的 V_corner 越小（还受向心加速度 / 各轴 a_max 约束）。
  3. 从终点倒推、从起点正推，把各段速度曲线拼成连续剖面（梯形或 S 曲线的多段衔接）。
  4. 执行时仍按插补周期吐脉冲；前瞻只改速度规划，不改几何插补本身。

9.3 和现网业务的对照 —— 为何用不上 ​

现网形态为何不需要前瞻
一条 Move1 / Move3 / 盘 goto单段点到点，段末本来就要停稳到位
时序里多条电机命令命令之间常有业务等待（吸液、读传感器），不是连续轮廓切削
无「连续折线/多段 G 代码」缓冲没有「下一段路径」可前瞻

结论：前瞻是连续轨迹数控的配套；现网是单段到达 + 业务节拍，保持现状即可。仅当未来出现「MCU 连续执行一长串折线/样条且不允许段段停稳」时，才在插补之上再谈前瞻。

9.4 三层概念速记 ​

text
① 路径插补     —— 多轴如何按几何比例发脉冲（现网：无）
② 单段速度规划 —— Acc/Const/Dec 或进给 F(t)（现网：有，单轴速度表）
③ 多段前瞻     —— 段间接力、拐角限速（现网：用不上）

10. 维护 ​

  • 本文描述现网 MCU 直驱 边界；FPGA 电机路径不在此列。
  • 插补 / 前瞻均为概念资料；落地实现前需单独设计评审。
  • 若后续引入多轴插补，应新增 docs/src 模块并在本夹追加专章；前瞻仅在「多段连续轨迹」成立后再议。
